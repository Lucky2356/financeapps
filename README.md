Приложение для домашней бухгалтерии: операции и счета, лимиты и цели, план/факт по месяцам,
прогноз денежного потока, портфель с ценами Московской биржи. Данные живут **на устройстве** — в
IndexedDB, зашифрованные паролем владельца. Связать компьютер и телефон можно через службу
синхронизации (`server/`): она хранит только зашифрованное и ключа от данных не имеет. Не хочется
связывать — данные переносятся файлом резервной копии.

| | |
|---|---|
| **Платформы** | Windows (NSIS + авто-обновление), Android (APK) |
| **Стек** | Next.js 16 (App Router, `output: export`), React 19, TypeScript 5, Tailwind 3, Radix UI, Recharts 3, Tauri 2 |
| **Хранилище** | IndexedDB, один документ состояния на профиль, `schemaVersion` 16 + миграции; шифрование AES-GCM, ключ из пароля (PBKDF2) |
| **Синхронизация** | Своя служба на Node без зависимостей (`server/`): сквозное шифрование, слияние по строкам; второе устройство подключается по QR-коду без имени и пароля |
| **Внешние сервисы** | MOEX ISS (котировки), smart-lab (фундаментальные показатели, десктоп), LLM — опционально и по ключу владельца |
| **Языки интерфейса** | Русский, английский (`lib/i18n/catalog.ts`, переключается на лету) |

> индивидуальной инвестиционной рекомендацией.

## Возможности

| Раздел | Что делает |
|---|---|
| **Учёт** | Доходы, расходы, переводы между своими счетами, разбивка чека по категориям; фильтры в строке списка (категория, период, счёт, тип) с состоянием в URL |
| **Счета** | Наличные, карты, накопительные, брокерские; мультивалютность с пересчётом в базовую валюту |
| **Категории** | Иконка и цвет из палитры на 130+ оттенков, подсказка иконки по названию, флаги «обязательная»/«подписка» |
| **Лимиты** | Лимит на категорию в месяц, перенос неизрасходованного остатка, предложение лимитов по истории |
| **Цели** | Пополнение с любого счёта, требуемый ежемесячный взнос, срок достижения |
| **Плановые** | Шаблоны (неделя/месяц/год) с авто-проведением наступивших операций и напоминаниями |
| **Долги** | Кредиты и займы, авто-платежи, стратегии погашения «лавина»/«снежок», влияние на капитал |
| **План/факт** | Таблица «категории × месяцы» в трёх полосах: план вписывается вручную, факт и разница считаются по операциям; на телефоне — месяц за раз, статьи карточками. План расходов и лимиты — одни цифры |
| **Прогноз** | Денежный поток на 30/90 дней с предупреждением о кассовых разрывах |
| **Аналитика** | Динамика по месяцам, структура доходов и расходов, тренды категорий, норма сбережений |
| **Отчёты** | Печатная версия с собственной вёрсткой и палитрой (`@media print`) → «Сохранить как PDF» |
| **Инвестиции** | Портфель по средней цене или по списку покупок, watchlist, отраслевая структура, налоговая оценка, ребалансировка, дивиденды |
| **Капитал** | Net worth со снимками во времени, а не только реконструкцией задним числом |
| **Импорт/экспорт** | CSV с авто-определением формата банка (Сбер, Т-Банк, Альфа, ВТБ), маппингом колонок и откатом импорта; экспорт CSV/JSON; полная резервная копия |
| **Профили и люди** | Несколько наборов данных у одного человека; несколько людей на одном устройстве — у каждого свой пароль и свои устройства |
| **Защита** | Пароль на данные (можно пропустить), 12 слов кода восстановления, «не спрашивать на этом устройстве» |
| **ИИ-ассистент** | Ввод операции текстом, разбор чека, коуч по бюджету — Claude / OpenAI / DeepSeek, выключено по умолчанию, ключ владельца |

Дополнительно: тёмная и светлая темы, две плотности интерфейса, крупный текст, скрытие сумм
одним нажатием, копейки по желанию, экран запуска на выбор, командная палитра и горячие клавиши
(в том числе в русской раскладке), онбординг-тур, уведомления, вопросики с пояснениями на каждом
экране.

## Архитектура

Одна сборка фронтенда обслуживает обе платформы. Серверной части у экранов нет: страницы
экспортируются статически и приходят пустыми, а цифры подставляет клиент из хранилища устройства.
Служба в `server/` — отдельная программа только для обмена зашифрованными данными между устройствами.

```mermaid
flowchart TD
    PAGE["app/*/page.tsx · пустая серверная оболочка"] --> HOOK["useApiPageData(initial, path)"]
    HOOK --> CLIENT["apiClient"]
    CLIENT --> LOCAL["LocalApiClient · REST-подобный роутер"]
    LOCAL --> STATE[("LocalState · один документ на профиль")]
    STATE --> ENC["EncryptingStorageAdapter · AES-GCM"]
    ENC --> SYNC["SyncingStorageAdapter · запись сразу, отправка фоном"]
    SYNC --> NS["NamespacedStorageAdapter · человек на устройстве"]
    NS --> IDB[("IndexedDB")]
    SYNC -.-> SERVER["server/ · служба синхронизации, только шифротекст"]
    LOCAL --> SERVICES["services/* · прогноз, рекомендации, налоги, рынок"]
    SERVICES --> MOEX["MOEX ISS · котировки"]
    STATE -.-> BACKUP["Резервная копия .json · перенос между устройствами"]
    CLIENT -.-> AI["LLM · opt-in, ключ владельца"]
```

**Как читается страница.** `page.tsx` — серверный компонент, который отдаёт типизированную
заглушку из `lib/data.ts`. Клиентская обёртка (`*-manager.tsx`, `*-view.tsx`) вызывает
`useApiPageData(initialData, "/transactions?…")`, тот идёт в `apiClient`, а он — в
`LocalApiClient`, который собирает ответ из состояния устройства. Один и тот же путь работает и в
браузере при `npm run dev`, и внутри WebView2 на Windows, и внутри Android WebView.

**`LocalApiClient`** (`lib/api/LocalApiClient.ts`, ~3900 строк) — единственный источник данных.
Он держит REST-подобную поверхность (`GET /transactions`, `POST /plan`, `POST /investments` и так
далее), чтобы экраны не знали, откуда приходят цифры, и чтобы вся работа с деньгами лежала в одном
месте: чтение страниц, запись, пересчёт балансов, деривации для графиков.

**Оболочка.** Tauri 2 c плагинами `fs`, `dialog`, `http`, `opener`, `process` на обеих платформах и
`updater` + `window-state` только на десктопе (у них нет Android-реализации). Разрешённые адреса
пришпилены в `src-tauri/capabilities/default.json`.

## Данные и миграции

Всё состояние профиля — один валидируемый Zod-схемой документ (`lib/api/local/schemas.ts`):

```ts
LocalState {
  schemaVersion; currency; theme; density; …          // настройки
  accounts[]; categories[]; transactions[];            // учёт
  budgets[]; goals[]; liabilities[]; recurringTransactions[];
  plans[]; planNotes[]; planMonths[];                  // план/факт
  investments{ portfolio[]; watchlist[]; … };          // портфель
  netWorthSnapshots[]; realizedInvestmentEvents[]; importBatches[];
}
```

- **Миграции** — `lib/storage/migrations/runLocalStateMigrations.ts`, текущая версия **16**.
  Каждая миграция поднимает документ на одну ступень; состояние, записанное старой версией
  приложения, читается новой без потерь.
- **Повреждённый документ не роняет приложение**: `salvageLocalState` отбирает то, что валидно,
  вместо того чтобы отвергнуть файл целиком.
- **Профили** — независимые документы в одном хранилище; переключение перезагружает приложение.
- **Резервная копия** — тот же документ в JSON; способ переезда для тех, кто не связывает устройства.
- **Синхронизация** — строки несут отметку времени правки и следы удалений, поэтому две правки с
  разных устройств сливаются по строкам, а не «кто последний, тот и прав». Спорная строка
  показывается владельцу, а не выбирается молча.

## Инварианты предметной области

Правила, которые легко нарушить и дорого чинить, вынесены в отдельные модули и закрыты тестами:

| Инвариант | Где живёт |
|---|---|
| Перевод между своими счетами — пара обычных операций с общим `transferId`; он двигает балансы, но не является доходом или расходом, поэтому исключается из итогов по выбору читателя | `lib/transactions/transfers.ts` |
| План — не учёт: плановые суммы никогда не смешиваются с фактическими операциями | `lib/api/LocalApiClient.ts` (`planFactPage`) |
| Операция хранится в валюте счёта; в базовую валюту она пересчитывается **на чтение** (`baseAmount`), а не при записи | `lib/transactions/base-amount.ts` |
| Фильтрация операций описывается URL-параметрами и одинаково применяется на сервере списка и в UI | `lib/transactions/filter.ts` |
| Отрасль бумаги берётся из собственной таблицы тикеров, а ручной выбор владельца её перекрывает | `lib/market/sectors.ts` |
| Импорт CSV создаёт недостающие счета и категории по именам из файла и откатывается одной кнопкой | `LocalApiClient.importCsvRows` / `undoLastImport` |
| Цвета графиков берутся из токенов темы (`hsl(var(--token))`), поэтому следуют теме и печати без JS | `lib/charts/palette.ts` |

## Сборка и запуск

```bash
git clone https://github.com/Lucky2356/financeapps.git
cd financeapps
npm install
npm run dev            # http://localhost:3000 — то же приложение в браузере
```

В браузере доступны все экраны и те же локальные данные; недоступны только нативные диалоги
файлов — вместо них обычная загрузка и выгрузка.

### Windows

Нужен Rust toolchain — подробности в [docs/WINDOWS_DESKTOP.md](docs/WINDOWS_DESKTOP.md).

```bash
npm run tauri:dev      # запуск в режиме разработки
npm run tauri:build    # установщик NSIS
```

### Android

Нужны Android SDK, NDK и JDK 17 — подробности и работа с ключом подписи в
[docs/ANDROID.md](docs/ANDROID.md).

```bash
npm run android:dev           # на подключённом устройстве
npm run android:build         # релизный APK (нужен keystore)
npm run android:build:debug   # отладочный APK, ставится без своего ключа
```

Готовые сборки — на странице [Releases](https://github.com/Lucky2356/financeapps/releases),
инструкция для пользователя — [docs/ИНСТРУКЦИЯ.md](docs/ИНСТРУКЦИЯ.md), установка — [docs/УСТАНОВКА.md](docs/УСТАНОВКА.md).

## Релизы и обновления

1. Версия поднимается в `package.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` и
   `Cargo.lock`; в `CHANGELOG.md` добавляется секция релиза.
2. Тег `vX.Y.Z` или ручной запуск [`desktop-release.yml`](.github/workflows/desktop-release.yml):
   гейты → сборка подписанного установщика → проверка подписи апдейтера против вшитого публичного
   ключа → генерация и валидация `latest.json` → публикация релиза с описанием из `CHANGELOG.md`.
3. То же задание собирает APK, подписывает его ключом из секретов GitHub и отказывается
   публиковать, если сертификат не тот, что уже стоит на телефоне.
4. Релиз выходит **предварительным**; всем он приходит после
   [`promote-release.yml`](.github/workflows/promote-release.yml).

Десктоп обновляется сам через `tauri-plugin-updater` (манифест `latest.json` в последнем релизе),
Android проверяет наличие новой версии и предлагает скачать APK. Подробности —
[docs/DESKTOP_UPDATES.md](docs/DESKTOP_UPDATES.md), чек-лист — [docs/RELEASE_CHECKLIST.md](docs/RELEASE_CHECKLIST.md).

## Тестирование и гейты

| Гейт | Команда | Что проверяет |
|---|---|---|
| Типы | `npm run typecheck` | `tsc --noEmit`, строгий режим |
| Стиль | `npm run lint` | ESLint с `--max-warnings=0` |
| Модульные | `npm run test` | **1095** проверок в 153 файлах (Vitest + Testing Library): деньги, миграции, шифрование, слияние, фильтры, сервисы, компоненты |
| Служба | `npm run test:server` | **78** проверок службы синхронизации, в том числе безопасности |
| Сборка | `npm run build:static` | статический экспорт — общий бандл обеих оболочек |
| E2E | `npm run test:e2e` | **188** проверок в 30 файлах сценариев (Playwright) против **собранного статического приложения**, а не дев-сервера |

E2E гоняются по реальному пути данных: сценарий засеивает встроенный пример через кнопку самого
приложения и дальше работает с IndexedDB так же, как пользователь. Отдельно есть «камера»
(`e2e/shots.spec.ts`, запускается вручную с `SHOTS=1`) — она не проверяет ничего, а снимает экраны
релиза, чтобы их можно было оценить глазами.

Перед коммитом Husky + lint-staged прогоняют ESLint, Prettier и связанные тесты; в CI дополнительно
работает CodeQL.

## Приватность и безопасность

- Данные на устройстве зашифрованы ключом из пароля; без пароля и без 12 слов их не открыть.
- Связка устройств — по желанию. Служба синхронизации получает только шифротекст: ключа у неё нет,
  и восстановить пароль через неё нельзя по замыслу. Не связывать — значит переносить данные файлом.
- Банковские логины и скрейпинг банков не используются; котировки берутся из публичного MOEX ISS.
- ИИ-ассистент выключен по умолчанию. При включении во внешний сервис уходит минимальный срез
  данных, по ключу самого владельца, с явным предупреждением в интерфейсе.
- Приватный ключ апдейтера и Android-keystore в репозитории отсутствуют и никогда в него не
  попадают. О найденных уязвимостях — [SECURITY.md](SECURITY.md).
