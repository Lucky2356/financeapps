# Служба синхронизации

Один процесс, одна база, **ноль зависимостей**. SQLite, тестовый прогонщик и
вывод ключей — всё встроено в Node. Обновление на сервере это `git pull` и
`systemctl restart`, а не разбор того, почему сегодня не ставится очередной
пакет.

## Что она умеет и чего не умеет

Хранит зашифрованные книги и раздаёт их устройствам одного человека. **Открыть
их она не может**: ключ выводится из пароля на устройстве и на сервер не
уезжает. Украв эту машину целиком вместе с базой, нельзя узнать ни одной суммы
и ни одного названия счёта.

Видно другое, и лучше знать это заранее: сколько у кого книг, какого они
размера и когда их последний раз правили.

**Почты у службы нет.** При сквозном шифровании письма для сброса пароля
бесполезны — сбрасывает код восстановления, — а приглашение на десять человек
раздаётся лично. Значит: ни SMTP, ни «письмо не пришло», ни попадания в спам,
ни ещё одного чужого сервиса в цепочке.

## Что нужно

- Node 22.6 или новее (в Debian 13 — из `nodejs` в backports либо с nodesource).
  На Node 24 флаг `--experimental-strip-types` не нужен: типы снимаются сами.
- Caddy, уже настроенный на ваш домен — он держит TLS.

## Установка

```sh
# Отдельный пользователь: службе незачем ходить дальше своей папки.
sudo useradd --system --home /opt/financeapps --shell /usr/sbin/nologin financeapps
sudo mkdir -p /opt/financeapps
sudo chown financeapps:financeapps /opt/financeapps

# Код.
sudo -u financeapps git clone https://github.com/Lucky2356/financeapps /opt/financeapps

# Пропуск управления. Только латиница и цифры — он ездит в заголовке HTTP.
openssl rand -base64 32 | tr -d '/+=' | head -c 40; echo

# Юнит.
sudo cp /opt/financeapps/server/financeapps.service /etc/systemd/system/
sudo systemctl edit financeapps          # сюда вписать FINANCE_ADMIN_TOKEN
sudo systemctl daemon-reload
sudo systemctl enable --now financeapps
systemctl status financeapps
```

Служба слушает **только 127.0.0.1**. Наружу она смотрит через Caddy — иначе к
ней можно было бы прийти по обычному HTTP в обход сертификата, и входной билет
уехал бы открытым текстом.

## Caddy

В ваш `Caddyfile`, внутрь блока домена:

```caddyfile
finance.ваш-домен.ru {
	# Поток событий нельзя копить в буфере: событие дошло бы через минуту
	# после того, как случилось. Отсюда flush_interval.
	reverse_proxy 127.0.0.1:8787 {
		flush_interval -1
	}
}
```

После правки: `sudo caddy fmt --overwrite /etc/caddy/Caddyfile && sudo systemctl reload caddy`

Проверка: `curl https://finance.ваш-домен.ru/health` — должно ответить
`{"ok":true}`.

## Приглашения

Регистрация только по приглашению, и другого пути нет.

```sh
curl -s -X POST https://finance.ваш-домен.ru/admin/invite \
  -H "Authorization: Bearer ПРОПУСК" | jq -r .code
```

Полученный код человек вводит в приложении: **Настройки → Свой сервер**, вместе
с адресом службы, желаемым именем входа и **паролем своей книги**. Приглашение
одноразовое.

Кто уже заведён и сколько занимает:

```sh
curl -s https://finance.ваш-домен.ru/admin/people -H "Authorization: Bearer ПРОПУСК" | jq
```

## Копии

Содержимое книг и так зашифровано — копию можно класть куда угодно.

```sh
# Ежедневно, хранить 30 штук.
sudo -u financeapps sqlite3 /var/lib/financeapps/finance.db \
  ".backup /var/lib/financeapps/backup-$(date +%F).db"
```

**Бэкап рядом с сервером — не бэкап.** Копию надо забирать на другую машину.

**Непроверенный бэкап — надежда, а не копия.** Раз в квартал: взять вчерашнюю,
развернуть в пустое место, войти, сверить итог месяца.

## Обновление

```sh
sudo -u financeapps git -C /opt/financeapps pull
sudo systemctl restart financeapps
```

Схема базы досоздаётся при запуске (`create table if not exists`), ставить
ничего не нужно.

## Проверки

```sh
npm run test:server     # из корня склада
```

Служба поднимается на случайном порту с базой в памяти, и по ней ходят обычным
`fetch` — то есть проверяется ровно то, что увидит устройство, включая коды
ответов.

## Что стоит знать наперёд

- **Простой замечают все.** Приложение продолжит работать местно, но
  синхронизация встанет, и об этом скажут.
- **Потерянные коды восстановления.** Кто-нибудь однажды потеряет и пароль, и
  код. Ответ будет один — «книга потеряна», — и лучше, чтобы человек услышал это
  **при регистрации**, а не в тот день.
- **По ответу службы видно, заведено ли такое имя входа.** Для десяти человек по
  личным приглашениям это не та цена, ради которой стоит усложнять вход, но
  знать об этом надо.
